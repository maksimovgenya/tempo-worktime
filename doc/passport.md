# Паспорт проекта: Веб-приложение учёта рабочего времени сотрудников

## 1. Общие сведения
- **Наименование проекта:** Time Tracker (Учёт рабочего времени)
- **Назначение:** Веб-приложение для фиксации рабочего времени сотрудников компании, запуска/остановки таймера задач, формирования отчётов по периодам и долгосрочного сохранения данных.
- **Язык интерфейса и документации:** Русский язык.
- **Стек технологий:** Next.js 15+ (App Router), React 19, TypeScript 5, Tailwind CSS v4, Lucide React, Motion.
- **Режим хранения:** Гибридный (Серверный JSON-файл в `data/timetracker.json` + `localStorage` браузера).

---

## 2. Реализованный функционал
1. **Управление сотрудниками (`components/EmployeeManager.tsx`):**
   - Добавление сотрудника (ФИО, должность, отдел, цвет бейджа).
   - Список команды в виде информативных карточек с инициалами.
   - Возможность удаления сотрудника с подтверждением.
2. **Интерактивный таймер задач (`components/TimerWidget.tsx`):**
   - Выбор сотрудника из списка.
   - Выбор категории задачи (Разработка, Дизайн, Созвон, Аналитика, Тестирование, Управление и др.).
   - Поле описания задачи.
   - Большое табло секундомера (`font-mono tabular-nums`).
   - Кнопки: «Старт», «Пауза», «Продолжить», «Завершить и сохранить», «Отменить».
   - Кнопка ручного внесения времени (если задачу забыли запустить вовремя).
   - **Защита сценария повторного пуска:** диалоговое предупреждение при попытке стартовать новую задачу во время работы текущей с возможностью сохранения накопленного времени.
3. **Отчёты и аналитика (`components/ReportView.tsx`):**
   - Быстрые фильтры периодов: «Сегодня», «Текущая неделя», «Текущий месяц», «Всё время».
   - Произвольный диапазон дат (календарь «С» — «По»).
   - Фильтр по конкретному сотруднику или всей компании.
   - Поиск по названию задачи или сотруднику.
   - Сводные карточки сотрудников с общим отработанным временем и прогресс-баром доли времени от общих часов компании.
   - Детальный журнал выполненных задач с точным временем старта/финиша и длительностью.
   - **Сценарий пустого отчёта:** специализированное дружелюбное состояние `EmptyReportState` при отсутствии записей за выбранный интервал с быстрой кнопкой сброса на «Всё время».
   - Экспорт отчёта в CSV с поддержкой кириллицы UTF-8 BOM.
4. **Сохранение данных и персистентность:**
   - Серверный API маршрут `app/api/timetracker/route.ts` производит чтение и запись в файл `data/timetracker.json`.
   - Клиентский хук `hooks/useTimeTracker.ts` мгновенно кэширует состояние в `localStorage`, гарантируя сохранение даже при сбоях сети или перезагрузке вкладки.
   - Маршрут `app/api/timetracker/reset/route.ts` позволяет в 1 клик восстановить реалистичные демонстрационные данные.
5. **Встроенная документация (`components/ReadmeView.tsx` и `README.md`):**
   - Инструкция по установке и локальному запуску.
   - Описание применённых моделей ИИ (Gemini 2.5 / 3.8 Flash, AI Studio Engine).
   - Примеры реальных промптов с кнопкой копирования в буфер обмена.
   - Анализ выявленных и устранённых ошибок.
   - Подробные чек-листы проверки основных сценариев (повторный запуск и пустой отчёт).

## 3. Выявленные ошибки и методы их решения

| № | Выявленная проблема / Ошибка | Причина возникновения | Метод решения в кодовой базе |
|---|------------------------------|-----------------------|------------------------------|
| 1 | **Погрешность и замедление таймера в неактивных вкладках** | Использование счетчика `setSeconds(prev => prev + 1)` в `setInterval`. Браузеры троттлят таймеры в фоновых вкладках до 1 раза в минуту для экономии энергии. | Счётчик времени рассчитывается по разнице реальных меток `Date.now() - lastResumeTimestamp` с добавлением ранее накопленных секунд `accumulatedSeconds`. Таймер всегда абсолютно точен. |
| 2 | **Потеря времени при повторном старте задачи** | Пользователь нажимал «Старт» для нового сотрудника или другой задачи, пока старый таймер работал, что приводило к перезаписи состояния без сохранения наработанного времени. | Реализован перехватчик: функция `switchTaskAndStartNew()`. При конфликте открывается модальное окно с выбором. Нажатие «Сохранить текущую задачу и начать новую» фиксирует первый интервал в журнале и запускает второй с 0. |
| 3 | **Деление на ноль (`NaN%`) при пустом отчёте** | При фильтрации за период без записей суммарное время равно 0 секунд. Деление `(empSeconds / totalSeconds) * 100` давало `NaN%`, ломая отрисовку стилей. | Добавлено условие: если `totalCompanySeconds === 0`, процент доли равен 0. Реализован компонент `EmptyReportState`, исключающий поломку разметки. |
| 4 | **Потеря данных при обновлении страницы или перезапуске** | Данные сохранялись только в памяти React. | Реализована двухуровневая модель персистентности: запись в файл `data/timetracker.json` через API + синхронизация с `localStorage`. |
| 5 | **Удаление сотрудника, у которого уже есть записи** | При удалении сотрудника его записи могли потерять имя при наивной связи по внешнему ключу. | В каждой записи `TimeEntry` сохраняется не только `employeeId`, но и неизменяемое `employeeName` на момент выполнения работы. |
| 6 | **Нечистая функция Date.now() и setState в эффектах (React 19)** | Правило `react-hooks/purity` в React 19 запрещает вызов `Date.now()` прямо в теле хука при рендере, а прямой `setState` внутри эффекта вызывает каскадные рендеры. | Логика секундомера переведена на `useSyncExternalStore` с внешней функцией подписки. Прошедшее время вычисляется через снапшот без нарушения чистоты функций. |

## 4. Протокол проверки сценариев (Тестирование)

### Проверка 1: Повторный запуск таймера
- **Действие:** Запуск таймера по задаче 1 -> Выбор другого сотрудника -> Нажатие «Старт».
- **Результат:** Появилось окно предупреждения о конфликте с указанием текущей задачи и набежавших секунд. При выборе «Сохранить текущую задачу и начать новую» первая задача записана в историю, новая задача успешно стартовала.
- **Статус:** Успешно пройден.

### Проверка 2: Пустой отчёт
- **Действие:** Выбор вкладки «Отчёты и периоды» -> «Произвольный период» -> выбор даты в будущем.
- **Результат:** Отобразился дружелюбный пустой экран с иконкой и пояснением. Никаких ошибок JavaScript, битых стилей или NaN. Нажатие «Показать всё время» восстановило полный список записей.
- **Статус:** Успешно пройден.

### Проверка 3: Сохранность данных
- **Действие:** Добавление сотрудника -> Создание записи -> Перезагрузка страницы F5.
- **Результат:** Все данные на месте, файл `data/timetracker.json` обновлен на сервере.
- **Статус:** Успешно пройден.
