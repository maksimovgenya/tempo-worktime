# Time Tracker — Веб-приложение учёта рабочего времени сотрудников

Веб-приложение для фиксации и контроля рабочего времени команды с интерактивным таймером задач, гибкими отчётами по периодам, защитой от потери времени при повторном старте и сохранением данных после перезапуска.

Разработано в рамках тестового задания с использованием современных ИИ-инструментов.

---

## 1. Запуск проекта

### Требования
- **Node.js**: версия 18.18+ или 20+
- **Менеджер пакетов**: npm / pnpm / yarn

### Установка и запуск
```bash
# 1. Клонирование репозитория (или распаковка архива)
git clone <URL_РЕПОЗИТОРИЯ>
cd timetracker

# 2. Установка зависимостей
npm install

# 3. Запуск сервера в режиме разработки
npm run dev

# 4. Откройте в браузере:
# http://localhost:3000
```

### Сборка production-версии
```bash
npm run build
npm run start
```

## 3. Примеры запросов (промптов) к ИИ

### Промпт 1: Разработка отказоустойчивого секундомера
```text
Спроектируй React-хук useTimeTracker для трекера задач. Главная проблема: браузеры засыпают
и троттлят setInterval в неактивных вкладках, из-за чего таймер начинает отставать.
Реализуй вычисление прошедшего времени через разницу реальных таймштампов (Date.now() - startTimestamp)
с поддержкой паузы, возобновления и аккумулирования ранее набежавших секунд.
```

### Промпт 2: Реализация файловой персистентности без настройки СУБД
```text
Напиши серверный слой сохранения данных на Next.js Route Handlers (/api/timetracker).
Данные должны сохраняться в локальный файл data/timetracker.json, создавая папку и файл при первом запуске.
Предусмотри возврат реалистичных вымышленных демонстрационных данных (сотрудники и задачи) при отсутствии файла
или ошибках чтения, а также эндпоинт POST /api/timetracker/reset.
```

### Промпт 3: Обработка сценариев «Повторный пуск» и «Пустой отчёт»
```text
Реализуй защиту двух критических сценариев ТЗ:
1) Если пользователь пытается запустить задачу, пока старый таймер ещё тикает, предотврати затирание данных.
Покажи пользователю диалог: сколько времени набежало по текущей задаче и предложи либо автоматически
сохранить текущую задачу в журнал и начать новую, либо отменить действие.
2) Если фильтр периода (например, произвольный диапазон) возвращает 0 записей, покажи дружелюбный
компонент пустого состояния без деления на ноль (NaN) и с кнопкой возврата на «Всё время».
```

## 4. Ошибки в коде, которые были найдены и исправлены

| № | Ошибка / Дефект | Причина проблемы | Как исправлено |
|---|-----------------|-------------------|----------------|
| **1** | **Рассинхронизация времени в фоновой вкладке** | Использование счетчика `setSeconds(prev => prev + 1)` внутри `setInterval(..., 1000)`. При переключении вкладок браузер сжимает частоту таймеров до 1 раза в минуту для экономии батареи, из-за чего терялись десятки минут. | Время рассчитывается по формуле `accumulatedSeconds + (Date.now() - lastResumeTimestamp) / 1000`. Тикающий интервал выполняет лишь функцию триггера перерисовки UI. |
| **2** | **Потеря времени при повторном старте задачи** | В наивной реализации нажатие на «Старт» при уже идущем таймере перезаписывало `activeTimer` новыми значениями, а накопленный интервал предыдущей задачи бесследно исчезал. | Добавлен перехватчик: функция `switchTaskAndStartNew()`, которая принудительно фиксирует текущую задачу в массив записей с точной длительностью и только затем стартует новую задачу с `00:00:00`. |
| **3** | **Деление на ноль (`NaN%`) при пустом отчёте** | В компоненте отчётов расчёт доли времени каждого сотрудника производился делением: `(empSeconds / totalSeconds) * 100`. Если записей за период нет, `totalSeconds === 0`, что приводило к `NaN%` и некорректным стилям ширины `width: NaN%`. | Добавлена проверка `totalCompanySeconds > 0 ? Math.round(...) : 0` и отрисовка специализированного компонента с пояснением и быстрыми подсказками. |
| **4** | **Сброс данных при обновлении страницы** | При хранении данных исключительно в `useState` перезапуск или перезагрузка вкладки очищала всех сотрудников и записи. | Реализована двухуровневая модель: моментальное сохранение в `localStorage` (optimistic state) + асинхронная запись в `data/timetracker.json` через API. При перезапуске приложения все данные восстанавливаются. |
| **5** | **Нечистая функция Date.now() и setState в эффектах (React 19)** | Правило линтера `react-hooks/purity` запрещает вызов `Date.now()` непосредственно во время рендера тела компонента/хука, а синхронный `setState` в `useEffect` провоцировал каскадный рендеринг. | Секундомер переведён на `useSyncExternalStore` с внешней функцией подписки. Прошедшее время вычисляется в виде снапшота в соответствии со спецификацией React 19. |

## 5. Проверка основных сценариев

### Сценарий 1: Повторный запуск таймера
1. Во вкладке **«Таймер задач»** выберите сотрудника (например, «Алексей Смирнов») и нажмите **«Старт»**. Секундомер начнет отсчёт.
2. Не нажимая «Завершить», выберите другого сотрудника («Елена Кузнецова») или введите новое описание задачи и снова нажмите **«Старт»**.
3. **Ожидаемое поведение**: открывается предупреждающее окно:
   > *«Таймер уже запущен! В данный момент ведётся учёт задачи... Набежало времени: XX сек. Что сделать с текущей задачей?»*
4. Нажмите кнопку **«Сохранить текущую задачу и начать новую»**.
5. **Результат**: время по первой задаче не потеряно и автоматически добавлено в журнал и отчёты, а новый таймер запущен с нуля.

### Сценарий 2: Пустой отчёт
1. Откройте вкладку **«Отчёты и периоды»**.
2. В строке выбора периода выберите **«Произвольный период»** и укажите диапазон дат в будущем (например, следующий год).
3. **Ожидаемое поведение**: вместо пустой сломанной таблицы или ошибок расчета процентов отображается блок:
   > *«Пустой отчёт: нет записей за выбранный период. За период не зафиксировано рабочих отрезков...»*
4. Нажмите кнопку **«Показать всё время»** — отчёт мгновенно возвращается к полной сводке и списку всех выполненных задач.

### Сценарий 3: Сохранение данных после перезапуска
1. Добавьте нового сотрудника в разделе **«Сотрудники»**.
2. Запустите таймер, остановите его через 5–10 секунд с описанием «Тестовая задача сохранения».
3. Полностью перезагрузите страницу (Ctrl+R / F5) или перезапустите dev-сервер (`npm run dev`).
4. **Результат**: добавленный сотрудник и новая запись времени сохраняются на месте.
